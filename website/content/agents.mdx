# Use with AI agents

Coding agents start dev servers, call them and hand you links. With tsp they use names instead of ports, find what
runs with one command, and give you a link you can open from anywhere.

## Commands agents rely on

| Command | Gives the agent |
| --- | --- |
| `tsp service status` | three ✓/✗ lines and exit 1 when local HTTPS isn't ready |
| `tsp routes --json` | the running `*.localhost` names: `name`, `port`, `pid`, `dir` |
| `tsp run <name> -- <cmd...>` | an app at `https://<name>.localhost`, with `PORT` and `HOST` set for it |
| `tsp list` | every dev server tsp can share, with its online link |
| `tsp doctor` | what the online side is missing, with the fix for each |

Every command prints what to do next when something is off, so an agent can recover without guessing. Commands that
need the user (a password for `tsp service install`, a Tailscale sign-in) say so.
