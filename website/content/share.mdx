# Share online

`tsp` finds the dev servers running on this machine and gives each one a link through Tailscale: public for anyone,
or private to your Tailscale network. The link is the same every time you run it.

## Share what is running

Start your dev servers the way you always do, each from its own project folder, then:

```bash
tsp                  # public links (Tailscale Funnel)
tsp --private        # only devices on your Tailscale network (Tailscale Serve)
```

```
Services:
  https://bigfoot.tail1234.ts.net/web/   →  127.0.0.1:4000
  https://bigfoot.tail1234.ts.net/api/   →  127.0.0.1:4100
  https://bigfoot.tail1234.ts.net/docs/  →  127.0.0.1:3001
```

The links work while `tsp` runs; Ctrl-C takes them down. `tsp --bg` keeps it running detached (logs in `./tsp.log`).
A server that starts later is picked up within a scan (20 seconds by default, `--interval` to change), and one that
restarts keeps its link.

## Public or private

| | `tsp` (Funnel) | `tsp --private` (Serve) |
| --- | --- | --- |
| Who can open the link | anyone on the internet | your devices and people on your Tailscale network |
| Webhooks from Stripe, GitHub, Slack | yes | no: they are outside your network |
| Your phone, a teammate | yes | yes, with Tailscale on their device |
| Extra setup | Funnel allowed in the admin console ([Install](/installation#3-tailscale-for-online-links)) | none |

## What gets found

Dev servers listening in the port range (3000–6000 by default) whose process is a web runtime: Node, Bun, Deno,
Python (uvicorn, gunicorn), Ruby, PHP, `go run`, Java, .NET, Elixir, Perl, and Docker-published ports with `--docker`.

```bash
tsp list                         # what would be shared, with its link, without sharing it
tsp --ports 3000-9000            # a wider range this time
tsp configure --ports 3000-9000  # ...or every time
tsp --all                        # every listener in the range, compiled binaries included
```

The project name is the folder that holds the nearest `package.json`, `go.mod`, `pyproject.toml`, `Cargo.toml` or
`.git`. If one folder runs two servers, the lower port gets `/<project>/` and the other `/<project>-<port>/`, and
`tsp` prints the map.

## What your app sees

Requests arrive the way they would on localhost: `Host: localhost:<port>`, the `/<project>` prefix removed, so CORS,
cookies and host allow-lists behave as they do locally. Apps that build absolute URLs from the request (OAuth redirect
URIs, canonical links) want the public host instead:

```bash
tsp --forward-host     # X-Forwarded-Host and X-Forwarded-Proto: https reach the app
```

Server-sent events stream and WebSockets upgrade, so hot reload works through the link too.

## A real setup

Four services of one product, each in its own folder:

```bash
cd ~/work/acme/services/agent     && bun run dev    # :3087
cd ~/work/acme/services/crawler   && bun run dev    # :3120
cd ~/work/acme/services/workspace && bun run dev    # :3122
cd ~/work/acme/apps/web           && npm run dev    # :4501
tsp
```

```
  https://bigfoot.tail1234.ts.net/agent/      →  127.0.0.1:3087
  https://bigfoot.tail1234.ts.net/crawler/    →  127.0.0.1:3120
  https://bigfoot.tail1234.ts.net/workspace/  →  127.0.0.1:3122
  https://bigfoot.tail1234.ts.net/web/        →  127.0.0.1:4501
```
